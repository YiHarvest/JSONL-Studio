# M2 editing, search, save and recovery

M1 continuation was approved by the user. M2 remains a local desktop application.

## Editing

Rust `Document` references the immutable indexed source through ordered source ranges and added byte buffers. Insert/delete split ranges; unchanged file contents stay on disk. Every edit carries a revision; stale edits fail. Applying an edit writes a recovery checkpoint before replacing the active buffer.

CodeMirror edits one JSON value, including multi-line Pretty input. Rust validates it, compacts whitespace outside strings, and retains integer/exponent tokens and duplicate object keys. Existing malformed lines can be repaired. Record editing/duplication is limited to 2 MiB; added edit bytes total at most 32 MiB. Untouched oversized or invalid-encoding lines can still be saved byte for byte.

New records append at the end. Duplicate inserts after the chosen record. Delete asks for confirmation and changes only the unsaved buffer until Save. Tree menus copy, search a node key and open its containing record in the editor.

## Search

The existing search field filters the loaded range immediately. The adjacent scope button starts whole-document raw text, key or scalar value search. Requests scan at most 2,000 records or enough pages to collect approximately 100 hits. The UI retains at most 500 hits, displays scan progress and can stop requesting more batches. The in-flight batch completes; stopping does not terminate a Rust thread.

Clicking a hit loads its record, switches to Tree, opens its pointer ancestors and extends array limits to the target index. The target is highlighted and scrolled into view. Matching is case-insensitive substring matching. Key/value search skips malformed and oversized preview records and uses serde's object semantics for duplicate keys; raw search checks each bounded preview.

## Save

Save and Save As choose a local JSONL/NDJSON destination. A same-directory random temporary file receives unchanged source ranges and edit buffers through streaming writes. It is flushed and synced; its index is checked before replacement. The source and existing destination metadata are checked immediately before rename. New destinations use no-clobber creation; overwriting another destination requires confirmation.

Untouched bytes, invalid encoding, BOM and line endings remain intact. Edited records use CRLF for a CRLF source and LF otherwise. When inserting after a final line without a terminator, a separator is added. Permissions of the existing destination, or original source for a new Save As file, are preserved. Symlink destinations are rejected.

Pre-commit failures retain the original file. Rename is atomic, and the parent directory is synced where supported. Metadata checks do not provide a transaction with unrelated external writers: an external write racing the final check/rename remains possible. If reopening fails after a successful rename, the error explicitly says the file was saved.

## Recovery

`recovery.json` lives in Tauri's local application-data directory. It contains the original path and metadata fingerprint plus added buffers/source ranges, or bounded scratch bytes for a pasted document. It is written through a private temporary file and atomic rename. No document contents enter browser localStorage.

Startup offers Restore/Discard. Restoring an edited disk document requires the original file with matching metadata; if it changed or disappeared, the checkpoint is retained and restore fails clearly. Closing an unsaved document confirms closure and preserves applied edits. CodeMirror text not yet applied is not a recovery checkpoint. Saving removes the checkpoint; switching documents after discard confirmation replaces it.

The application holds one active document and one recovery checkpoint. Recovery is local and is not a backup of the entire original large file.
